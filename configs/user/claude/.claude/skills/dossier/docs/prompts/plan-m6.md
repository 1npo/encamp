## Format of the plan

Write it to `SKILL/docs/plans/012-m6-plan.md`, following the project's planning-docs rules (the `claude-planning-docs` skill). The human starts each session with one line, such as "Start phase 1 as outlined in docs/plans/012-m6-plan.md", and that line must be enough. Do not write a copy-and-paste prompt for Sonnet. The plan has:

1. **Summary**: what M6 delivers in five lines or fewer, and the phase cuts.
2. **Shared rules**: carry over plan 011's section 2 with the M6 changes (branch `feat/dossier-m6`, the skills to load, never-touch list, scratch discipline, environment variables, tests first with the failing line recorded, no weakened checks, stop and report if the code contradicts the plan, tick the checkbox in the same commit, the C# and TS "do not wait" rule extended to all M6 judgement calls, and the truth folder rule above).
3. **Spec versus code**: every place where the spec and the code disagree or where the spec assumes something the code does not do (the freshness BAN is one; check the rest), each marked "plan can absorb it" or "needs a decision from the human", with your default.
4. **Triage of the M5 and M4 findings**: one table, every finding, with its disposition (task id, `post-v1.md` entry, or no action).
5. **Decisions**, numbered D1, D2 and so on, with the reason.
6. **Phases**, each a heading `## Phase <n>: <title>`, used identically everywhere. Each is self-contained and holds: what to read first and which skills to load; a first step that checks what earlier phases recorded; an ordered list of tasks; deliverables and how each is checked; the cut line; acceptance criteria; and the branch and release steps. Every task has: an id (M6-1, M6-2, ... numbered across phases), a goal, the exact files to touch, the interface or data shape, step-by-step instructions, a done-check that can be run (a command and its expected result), a suggested commit message, and a checkbox. Each task can be finished and committed on its own and the suite passes after every one. No task needs design judgment. The cut line must never drop tests for anything new, V2 to V5, the plan 008 checks on anything new, or the definition-of-done verification. Say which items drop first if time runs short (the spec's cut line: P1 cards, then Tier B polish). Each phase says to write its results back into the plan under "Results".
